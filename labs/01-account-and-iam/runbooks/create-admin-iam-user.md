# Create an admin IAM user

## Outcome

You have an IAM user for daily work (with MFA), and you sign in as that user instead of root.

## Prerequisites

- [Enable MFA on the root user](enable-root-mfa.md)
- Password manager ready for a new IAM user password or access keys (this runbook uses console password sign-in)
- Time: ~10 minutes

## Steps

1. Sign in as the **root user**.
2. Open **IAM** → **Users** → **Create user**.
3. User name: something obvious (for example your first name or `lab-admin`). Do not use `root`.
4. Enable **Provide user access to the AWS Management Console** and set a console password (autogenerated or custom—store it in your password manager).
5. On permissions, attach the AWS managed policy **`AdministratorAccess`**.

   This lab account is for learning only. For production you would use narrower policies.

6. Finish creation. Open the new user → **Security credentials** → **Assign MFA device** and set up MFA the same way you did for root.

   - **Verify:** MFA shows as active on the IAM user.

7. Copy the **console sign-in URL** for IAM users (IAM → **Dashboard** → **AWS account** section, or the user’s **Security credentials** page). It looks like `https://`<account-id>`.signin.aws.amazon.com/console`.
8. Sign **out** of root. Sign in with the IAM user URL, user name, password, and MFA.

   - **Verify:** The console works. The top account menu shows the IAM user name, not “root”.

## Troubleshooting

| Symptom | Likely cause | What to try |
| --- | --- | --- |
| Cannot sign in at main AWS login | IAM users use the account-specific URL | Use the IAM sign-in link from step 7 |
| Access denied everywhere | Policy not attached | As root, confirm `AdministratorAccess` on the user |
| MFA required but not set | User policy or account setting | Complete step 6 |

## Teardown

Keep the IAM user. Do not delete it. Stop using root for day-to-day work.
